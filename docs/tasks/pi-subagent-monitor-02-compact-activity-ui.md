# Pi subagent monitor 02 — Compact popover with meaningful activity

Status: **ready; not implemented**. Depends on [01](./pi-subagent-monitor-01-source-health.md) and follows the [plan](../plans/pi-subagent-monitor.md).

## Outcome

The existing composer subagent popover communicates a child's task, agent type, state and last meaningful available action at a glance. One optional inline detail preview avoids opening a full session for ordinary status checks; full-session navigation remains direct. There is no new dashboard.

## Code to inspect

- `packages/app/src/subagents/track.tsx`, `track-presentation.ts`, `select.ts`, `provider-store.ts` and corresponding focused tests.
- `packages/app/src/composer/tracks.tsx` (`ComposerTrackPill`, `ComposerTrackRow`; 620px/440px panel and compact sheet).
- `packages/app/src/panels/provider-subagent-panel.tsx` (existing detail view and timeline retrieval).
- `packages/app/src/types/stream.ts` (`tool_call`, `assistant_message`, notifications and timestamps).
- Existing menu focus, i18n, theme, reduced-motion and desktop/narrow-width conventions.

## Implement

1. Retain the existing pill and counts, including mixed-state reporting. Improve the opened panel, not its entire host. Show each child's concise task text (up to two lines), actual lifecycle state (running/completed/failed/canceled), agent type or trusted provider subtitle where provided, and elapsed time from `createdAt` when timestamp is valid. Display unknown values as absent, not as invented values. Don't use heartbeat-like descriptor `updatedAt` as last activity.
2. Use already-streamed `useProviderSubagentStore` timeline events to derive a **bounded, stable** "latest meaningful activity" label. Prefer a last relevant tool call/tool status or explicit short assistant response and its real event timestamp. Do not show reasoning, unbounded output, raw tool arguments, last user prompt labeled as progress, or inferred semantic review approval. If history has not been observed, show a neutral unavailable/awaiting-activity state. Guard multiline, long paths, invalid timestamps and empty text; cap excerpts.
3. Only when useful, allow a **single** expanded inline preview with full task and at most ~3 distinct recent meaningful events or explicit last response. Prefer local expanded-id state, stable child identity, and a single existing bounded timeline fetch **on user expansion if local cache is absent**; no fetch for every row or every panel open, no independent polling. If the current `MenuSurface` cannot safely support the disclosure without extra complexity, use an equivalent simple sibling "Details" action. Keep the main row's one-press full-session navigation.
4. Any action controls must be siblings of the row's Pressable, not nested inside it. Keep focus, Escape/close, Enter/Space, compact sheet interaction, click targets and accessibility labels correct; `closeOnSelect` should correspond to navigation versus expansion. Do not globally modify `ComposerTrackRow` unless a proven minimal change is required.
5. Show running/failed/attention items ahead of finished ones while preserving stable relative order within buckets. Avoid rows bouncing around on every event, and keep "Archive finished" semantics: **provider rows are hidden locally**, not deleted from Pi session history. No guessed grouping by C1/C2 or autogenerated reviewer/fixer labels.
6. Keep the list affordable with many rows: compute brief event excerpts once for the visible/expanded child or via narrow memoized selectors; avoid rerendering the entire list for each streamed token and avoid scanning whole timeline arrays on every paint. No new packages, database, LLM-generated summaries, or model-name inference.

## Acceptance and minimal tests

- Realistic mixed fan-out: 1 running + multiple finished, repeated agent types, failed/canceled child, provider & Paseo-managed child. Correct distinction and readable labels without opening sessions.
- A reviewer may finish while reporting defects: UI says "Finished" and possibly "Last response", **never** "Approved" based solely on exit code. Explicit no-activity state for old/unavailable history.
- Active child shows a new meaningful tool event, with no process-status-as-activity mistake; repeated token streaming does not rerender all rows.
- Inline preview, if included, does not trigger navigation; full-session open still works. Any fetch is bounded, on demand, and for only one expanded child.
- Test pure projection logic and one meaningful interaction in existing subagent tests, targeted app typecheck/format/lint. Manually inspect desktop and ~360px compact layout, scrolling and keyboard/assistive text where runtime exists; report unavailable manual checks plainly.

Commit this task alone, update status/test evidence. Do not change backend wire schemas for cosmetic UI details.
